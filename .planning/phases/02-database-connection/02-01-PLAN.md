  <files>

  <action>
Create CredentialManager class in src/automated_data_cataloger/connection/credentials.py:
- __init__(service_name: str = "AutomatedDataCataloger") to initialize keyring service
- store_password(username: str, password: str) -> None: Store password in OS keyring using keyring.set_password()
- get_password(username: str) -> str | None: Retrieve password from keyring using keyring.get_password()
- get_from_env(key: str) -> str | None: Get credential from environment variable using os.getenv()
- build_config_from_env() -> DatabaseConfig: Build DatabaseConfig from environment variables (DB_TYPE, DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD or keyring fallback)

Environment variable naming convention:
- DB_TYPE (postgresql or mysql)
- DB_HOST (hostname)
- DB_PORT (port number)
- DB_NAME (database name)
- DB_USER (username)
- DB_PASSWORD (password if not using keyring)
- DB_SSL (true/false)
- DB_TIMEOUT (timeout in seconds)

Create test suite in tests/connection/test_credentials.py:
- Test store_password and get_password with mocked keyring
- Test get_from_env with environment variables set
- Test build_config_from_env creates valid DatabaseConfig
- Test keyring fallback when DB_PASSWORD not in environment
- Use pytest monkeypatch for environment variable testing
- Use unittest.mock for keyring mocking

Follow patterns from 02-RESEARCH.md Pattern 4 (Secure Credential Management).
Add type hints for all methods. Handle missing environment variables gracefully (return None or raise clear errors).
  </action>
