<task type="auto">
  <name>Task 1: Create catalog data models</name>
  <files>src/data_cataloger/cataloging/models.py</files>
  <action>
Create three data models following the research patterns:

1. **TableCatalog (Pydantic BaseModel)** - LLM response schema for structured outputs:
   - `description: str` with Field(description="Business purpose in 1-2 sentences")
   - `sensitivity: Literal["PII", "financial", "public", "internal"]` (use Literal not validators - OpenAI strict mode compatible)
   - `example_queries: list[str]` with Field(description="2-3 example SQL queries")
   - Use simple types only (str, list, Literal) - no validators, computed fields, or complex unions per research Pitfall 1

2. **CatalogEntry (frozen dataclass)** - Immutable catalog entry:
   - `table_name: str`
   - `description: str`
   - `sensitivity: str`
   - `example_queries: list[str]`
   - Matches TableCatalog structure but as dataclass for storage

3. **CatalogState (dataclass)** - State manager for sequential processing:
   - `entries: dict[str, CatalogEntry]` with default_factory=dict
   - `add_entry(entry: CatalogEntry) -> None`: Add catalog entry to state
   - `get_parent_context(table: TableMetadata) -> list[CatalogEntry]`: Extract already-cataloged parent tables from FK references
     - Get unique parent table names from table.foreign_keys
     - Return list of CatalogEntry for parents that exist in self.entries
     - Filter out missing parents (might be circular deps or not yet processed)

Add comprehensive docstrings explaining:
- TableCatalog: Why Literal instead of Enum (OpenAI compatibility)
- CatalogEntry: Why frozen dataclass (immutability)
- CatalogState.get_parent_context: How it enables context-aware analysis

Use typing.Literal from Python 3.11 (project requires-python = ">=3.11").
Import TableMetadata from data_cataloger.schema.models for type annotations.
  </action>

  <done>models.py exports TableCatalog, CatalogEntry, CatalogState with correct type signatures and passes mypy strict mode</done>
</task>
