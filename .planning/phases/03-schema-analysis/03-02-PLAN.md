Create PostgreSQLExtractor class with information_schema-based extraction methods following 03-RESEARCH.md examples (lines 312-424):

**Class structure:**
```python
class PostgreSQLExtractor:
    """PostgreSQL schema extractor using information_schema views."""
```

**Method 1: get_tables(connector: DatabaseConnector, schema: str = 'public') -> list[str]**
- Query: `SELECT table_name FROM information_schema.tables WHERE table_schema = %s AND table_type = 'BASE TABLE' ORDER BY table_name`
- Returns: List of table names (strings)
- Filter to BASE TABLE only (excludes views, system tables)
- Default schema to 'public' (PostgreSQL standard)

**Method 2: get_columns(connector: DatabaseConnector, table: str, schema: str = 'public') -> list[ColumnMetadata]**
- Query: `SELECT column_name, data_type, is_nullable, ordinal_position, column_default FROM information_schema.columns WHERE table_schema = %s AND table_name = %s ORDER BY ordinal_position`
- Convert is_nullable: `(row[2] == 'YES')` - critical to avoid all columns appearing nullable
- Returns: List of ColumnMetadata objects

**Method 3: get_primary_keys(connector: DatabaseConnector, table: str, schema: str = 'public') -> list[str]**
- Query: Join information_schema.table_constraints + key_column_usage, filter constraint_type='PRIMARY KEY'
- ORDER BY kcu.ordinal_position (maintains column order in composite PKs)
- Returns: List of column names (strings)

**Method 4: get_foreign_keys(connector: DatabaseConnector, table: str, schema: str = 'public') -> list[ForeignKeyMetadata]**
- Query: Join key_column_usage + referential_constraints (see 03-RESEARCH.md lines 387-424)
- ORDER BY constraint_name, ordinal_position (critical for composite FKs)
- Returns: List of ForeignKeyMetadata objects (one per column in FK)
- Include self-referencing FKs (e.g., categories.parent_id -> categories.id)

Use `with connector.connection.cursor() as cur:` pattern from Phase 2. Execute queries with parameterized %s placeholders (not f-strings - SQL injection prevention). Import DatabaseConnector from data_cataloger.connection.base, models from data_cataloger.schema.models.

Follow exact SQL queries from 03-RESEARCH.md to avoid pitfalls (nullable conversion, composite FK ordering, self-references).
